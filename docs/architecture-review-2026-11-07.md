## 当前结构与后续维护

### 静态生成与数据契约

Markdown、YAML、TOML 是内容源，Hugo 输出 HTML、JSON 和静态资源。站点没有需要调优的在线数据库或自建运行时接口。CMS 的 GitHub backend 将编辑结果写回仓库，随后触发构建。数据优化应优先放在生成阶段，避免每个访客重复处理同一内容。

照片规范化、响应式图片、搜索和侧栏查询已经分别有明确入口。照片数据按语言缓存，缩略图按原图地址复用；不应另外再维护一份首页照片清单。搜索保留全文，不能为缩小索引直接截断正文，否则会改变可搜索范围。

### 客户端边界

统计代码从 `custom.ts` 拆出后，总入口仍约 1,590 行，继续包含语言、照片布局、时钟和菜单等功能。后续调整这些功能时可按功能分模块，并保持同一初始化入口；仅为降低文件行数而移动所有代码，收益有限。此次先分离边界独立、便于验证的统计部分。

渲染模块与业务协调已分开：`experience.ts` 管理入口和导航，`hologram.ts`、`fluid.js`、`glass-transition.ts` 各自负责绘制，音频由 `site-audio.ts` 统一提供分析数据。改动加载或数据结构时，应避免另起 FFT、并行播放器或重复动画循环。

`assets/ts/page-transitions.ts` 是仓库中的历史入口，但当前提交的 head 模板没有引入它。本地原有未提交的 `head/custom.html` 含有对应引用，不能将这个工作树状态当成线上事实。维护转场时先确认实际加载的脚本，不要仅凭源码文件存在就判断其正在生效。

### 生命周期与初始化

主题入口等待 DOMContentLoaded，custom 脚本保持 defer 顺序，以便安装存储兼容处理。慢脚本、慢人物图场景已验证一次初始化；普通文章与跳过开屏不下载开屏图片。

音乐跨文档导航会重新创建播放器，当前使用播放偏好、音量和时间恢复接续。要做到跨页完全无缝播放，需要改变页面导航架构；这会扩大行为与特效改动范围，不能只通过增加恢复定时器解决。

### 模板与依赖

项目的 `layouts/` 和 `assets/` 覆盖主题资源，但主题目录自身也有历史定制。上游升级应逐项对比这两层，不能直接覆盖 `themes/stack/`。Lato、PhotoSwipe、KaTeX、Three.js 的本站副本保留各自版本和许可；后台 Sveltia 仍由固定版本 CDN 提供。

GitHub Pages 和 Netlify 配置均固定 Hugo 0.164.0。部署子路径为 `/personal-webpage/`，模板中的资源链接需要保留 `relURL` 和站点路径元数据。CMS 的仓库与 URL 配置也要与目标部署匹配。

## 验证与观察

- 原加载优化的独立构建：124 个 Hugo 页面，500 个输出文件。受控慢网两次测试中，人物首次绘制均值约从 21.5 秒降至 6.0 秒；固定 GPU 对比的点数、着色器和轮廓一致。
- 手机 390×844：对齐字体后，入场与内容区主要几何差异均为 0px，滚动结束状态和文本一致。原先 30px 差异来自基线测试未加载 Lato。
- 搜索：11 篇解码后的全文逐字一致；`<script>`、`>1000px`、`created:>本周一`、`项目` 四组查询的结果及高亮一致。127 个 HTML 文件排除脚本后内容一致。
- 浏览器原生的 `ViewTransition opt-in disabled` 取消日志在已发布基线与候选均可复现；已测页面可正常显示。此次没有添加全局异常拦截来隐藏这些日志。

最终结构调整后的独立构建通过且没有警告；统计模块的周、小时、371 个热力格及运行天数 DOM 与调整前完全相同。统一 PhotoSwipe 配置后，同源图片放大、打开动画后的 Escape 关闭通过，无本地 404 或页面错误；人物、音乐、跨页暂停与音量恢复检查通过。搜索与 127 个 HTML 的内容对照再次通过。线上发布结果以对应提交的 GitHub Actions 和本次交付记录为准。
