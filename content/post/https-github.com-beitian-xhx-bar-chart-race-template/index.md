最近做了一个数据可视化视频：把 2025 年 7 月到 2026 年 6 月国产二次元手游的全球月度流水做成「动态条形图竞赛」（Bar Chart Race）的形式，竖屏 1080×1920，赛博朋克风格。整个过程从一段需求描述开始，最后沉淀成一个可复用的模板。记录如下。

## 一、需求

最初的描述大致是：主题是国产二游全球月度流水对比，时长 90–120 秒，竖屏适配短视频平台，深色背景加霓虹描边，主视觉用动态条形图竞赛，每个游戏固定一个主题色，条形末端显示具体数字，过渡动画用 easeInOutCubic。还附带了一份游戏配色方案（原神金色、星铁星空蓝、绝区零青绿等）。

需求本身已经很具体，但动画的细节效果，还是要一版版调出来。

## 二、技术选型

视频动画类需求，最终选了 Remotion：用 React + TypeScript 描述每一帧的画面，渲染交给框架处理。相比手动用 Canvas 逐帧绘制，Remotion 的组件化对"条形随数据变化"这种场景更友好——每个条形就是一个组件，数据变了组件重渲染，帧间动画由 Remotion 的时间机制驱动。

预览用 Remotion Studio（npm start），最终渲染走命令行（npm run build）：内部通过无头浏览器逐帧截图，再交给 ffmpeg 编码成 MP4。

## 三、数据准备

数据是重头。范围是 12 个月、7 款游戏（原神、星铁、绝区零、鸣潮、崩坏3、明日方舟、碧蓝航线），单位亿元人民币。来源主要是 GachaRevenue（revenue.ennead.cc）、Sensor Tower 的移动端数据，以及七麦、二观、ixbt.games 等第三方月度报告，再互相交叉核对。口径上，原神、星铁、绝区零、鸣潮用全球全平台估算，明日方舟、碧蓝航线、崩坏3 以移动端为主加 PC 系数。

除了数值，每月的关键事件也做了标注（比如 2025-11 星铁 Cyrene 单月 25 亿、2026-01 原神"冬夜旅人"登顶、2026-06 鸣潮赛博朋克联动超过三款米哈游产品）。这些事件会显示在时间轴附近，用来解释流水波动的原因。

## 四、迭代过程

第一版按最初的规格做，问题不少，后面几乎是把"动画手感"重做了一遍：

1. 时长压缩：从 90–120 秒压到 30 秒，柱形图的伸缩感要加强；再后来干脆取消固定时长，由月份数量与过渡帧数自动决定；
2. 数据改成累计流水：单月数值波动太碎，累计更能看出整段排名竞争的过程；
3. 排名过渡连贯：排名变化时柱子要平滑上下移动，而不是跳变；伸缩过程不留间隔；
4. 月份之间也要过渡：不要每个月独立成一张图，而是连续推进，月份标签交叉淡入淡出；
5. 重构成可复用模板：只要填一份数据文件，就能生成完全不同的视频，不用改组件代码；
6. 再封装成 skill 形式：触发时自动弹出配置问卷（主题、数据模式、单位、画幅、配色、节奏、数据内容），生成数据文件后直接渲染。

到这一步，这个项目就不只是"一个视频"，而是一条从需求到成片的自动化流水线。

## 五、运行逻辑

整个视频是一条单一时间线，分成几个阶段：标题入场 → 条形入场 → 逐月过渡 → 最终定格 → 结尾卡。

核心逻辑在条形图组件里：

- 累计模式：配置为 cumulative 时，先按月份累加出每条目的累计值，动画展示的是累计曲线；
- 月份插值：把全局时间经缓动函数（默认 sin）映射成 0\~1 的进度，再换算成"第几个月"，取相邻两个月做插值——条形长度、排名位置、坐标轴最大值都在两个月之间平滑过渡；
- 排名动画：每个条形记录它在"上一月"和"下一月"的排名，垂直位置按进度插值，排名变化时看起来就是柱子平滑地上下换位；
- 过渡与事件：月份标签交叉淡入淡出，事件文本随月份切换；
- 视觉层：深色渐变背景、纯 CSS 实现的粒子（60 个点循环浮动，不引第三方库）、第一名脉冲、底部进度条、数据来源水印；
- 结尾：最终排名面板按累计值降序排列，前三名带奖牌和占比，最后是署名结尾卡。

所有布局参数、动画时长、配色都收敛到一份默认配置里，用户数据通过深度合并覆盖默认值，这也是"填数据即出片"的关键。

## 小结

这个项目最大的收获不是动画本身，而是"把一次性需求抽象成可复用模板"的过程。数据与表现分离之后，同一套模板换数据就能出片；再封装成 skill，连配置都变成问卷式输入。后面再有类似的数据可视化需求，基本就是填表和渲染两步。
