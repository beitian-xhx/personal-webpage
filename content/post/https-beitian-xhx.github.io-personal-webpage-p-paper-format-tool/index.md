最近写了一个纯本地的论文排版工具：给一篇格式混乱的毕业论文草稿，按学校模板的格式要求自动重排，全程只改格式、不动一个字。起因很简单——毕业论文的格式要求实在太多了：字体字号、行距、首行缩进、标题层级、页码、目录，每一项都有硬性规定，手动调一遍又慢又容易漏，而且不同学校的模板还不一样。

## 一、核心设计：只改格式，不动内容

这个工具最开始的定位就很明确：它不是"重写论文"，而是"重排格式"。所以第一条铁律就是\*\*内容不变性校验\*\*——排版前把正文、表格、脚注/尾注/批注的全部文本快照下来，排版后再快照一次逐段对比，只要正文有任何改动，\*\*默认拒绝输出\*\*（退出码 2）。想强制放行，必须显式加 \`--force\`。

这道硬校验帮我挡掉了不少隐患：目录域插入、页码重计这类操作，一不小心就可能碰到正文。有了它，工具只敢改格式，内容一个字都不会动，这也是用户敢放心把论文交给它的底气。

## 二、从学校模板提取规则

排版的目标格式不是写死的，而是从学校模板里提取：传入一个模板 docx，工具解析它的页面设置（纸张、页边距）、标题样式、正文样式，提取成一套规则再应用到草稿上。没传模板就用内置的国标默认值。

规则模型做成可空 dataclass，每个字段"None 表示不改这项"，模板提取的规则和内置默认规则可以局部覆盖合并——这个设计为以后按学校扩展规则留了口子。

## 三、结构识别

排版前先要搞清楚草稿的段落结构：封面 / 摘要 / 目录 / 正文章节 / 参考文献 / 致谢。识别靠三重启发式：关键词（摘要、目录、参考文献、致谢）+ 编号模式（第X章 / 一、/ 1.1 / （一））+ 样式名（Heading / 标题）。

识别出区域后，每类区域按不同规则处理：

- \*\*正文归一化\*\*：宋体小四、行距、首行缩进 2 字符——用的是 Word 的 \`firstLineChars\` 字符单位，随字号自适应；

- \*\*标题样式化\*\*：1-3 级标题应用模板样式，并设置大纲级别（Word 导航栏可用）；

- \*\*页码\*\*：多节文档的正文节页码从 1 重计；单节文档自动在正文前插入分节符再重计，不用手动处理；

- \*\*表图题注\*\*：表题黑体居中、图题宋体居中，表格与图正文内容零改动；

- \*\*公式编号\*\*：识别行尾 \`(N-N)\` 编号的公式段居中处理，带数学符号启发式防误判；

- \*\*目录\*\*：插入 TOC 域，Word 里右键"更新域"一键生成。

## 四、几个容易翻车的地方

- \*\*中文字体要写 \`w:eastAsia\` 属性\*\*，光设 \`font.name\` 是不够的，西文字体反而会把中文渲染成默认字体；

- \*\*页脚保护\*\*：页脚已有作者/页码时不直接清空，页码追加到新段落——防止把别人辛苦排好的页脚清掉；

- \*\*首行缩进\*\*：不能用固定磅值，得用字符单位，否则字号一变缩进就不对了；

- \*\*公式居中\*\*：不能见数字就居中，得配合数学符号特征判断，不然会把普通行尾数字误判成公式。

## 五、多格式草稿适配

草稿不一定是 docx。我加了一层文件类型嗅探（按文件魔数识别，不信任扩展名）：docx / txt / md / html / rtf 都能处理——能原生读的原生读（txt/md/html/rtf 提取正文后排版），老式 .doc 用本机 Word/WPS 自动转换。加密 docx、PDF、Excel 误传这类情况给出精确提示，不再笼统报一句"不是有效 docx"。编码上支持 UTF-8 / GBK / UTF-16。

## 六、双入口：Web UI + 命令行

普通用户用 Web UI：本地起服务自动开浏览器，上传草稿 → 选模板（可选，自动预览提取到的规则）→ 一键排版下载。支持\*\*批量排版\*\*，一次最多 20 篇，实时进度条显示每篇状态，完成后下载 zip（每篇结果 + 修改报告 + 汇总报告）。全程本地处理，不上传任何服务器。

高级用户用命令行，还能输出修改报告：

\`\`\`bash

python -m src.main 草稿.docx --template 学校模板.docx -o 排版后.docx -r 报告.md

\`\`\`

也可以打包成单文件 exe：双击开 Web UI，带参数走 CLI，一个程序两种用法。

## 七、用真实高校模板验证

为了证明不是玩具，我从高校官网下载了 6 个真实论文模板（东南大学本科毕业设计参考模板、南航×2、上交电院开题答辩评审表、常州大学×2），做端到端测试：提取规则 → 排版 → 校验内容零改动，全部通过。另外还有 53 项边界场景回归断言（含 txt/md/html 适配与类型嗅探）、25 项 Web API 集成测试（含真实 .doc 自动转换）。

## 小结

这个项目让我对 OOXML 有了不少新认识：字体要写 eastAsia、分节符和页码重计的关系、\`firstLineChars\` 字符缩进这些细节，都是实际动手才踩明白的。最有价值的还是"内容不变性校验"这个设计——它把"只改格式"从一句口号变成了一道可验证的硬约束，工具敢放心大胆地改，用户也敢放心地交给它。
